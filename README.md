# 论文对照阅读器

面向中文与英文论文的 Windows 桌面阅读器。支持单栏阅读、选字高亮、文字备注、阅读位置恢复；可导入已有的中英两份 PDF 对照阅读，也可翻译全文生成中文 PDF，并联动翻页、滚动和缩放。

## 使用

1. 运行 `PaperReader-Setup-0.1.11.exe` 安装。安装包附带 PDFMathTranslate-next 2.9.0、BabelDOC 0.6.3 以及字体和模型，无需安装 Python 或 Node.js。桌面运行时已精简未使用的网页界面、测试文件和编译缓存，安装器采用 ZIP 压缩。已有版本可退出软件后直接升级，原有本地记录继续使用。
2. 点击“打开论文”（Ctrl+O）或将一份 PDF 拖入窗口。中文论文默认单栏显示，阅读和批注无需配置 API。已有两个版本时，点击“导入中英对照”，或同时拖入两份 PDF，确认英文在左、中文在右后点击“开始对照阅读”；可交换左右，也可为已打开的英文论文补充中文文件。配对、阅读位置和两侧批注保存在本机，重新打开英文 PDF 即可恢复，移动中文源文件不影响阅读。可切换单栏原文、双栏对照和单栏中文译文。
3. 选中文字后，旁边会出现带放大镜的“询问”按钮，词语、句子和段落都可以选。点击后在侧栏输入问题，或选择“解释术语”“解释这句话”“在本文中有什么作用”；按 Enter 发送，Shift+Enter 换行，选字后也可按 Alt+Q 进入询问。发送会使用“翻译设置”中配置的服务及模型，并发送选区和相关论文片段。支持追问、停止、手动重试、复制、保存为新备注和查看/删除本机会话；通过校验的出处可点击跳回对应版本的页面。问答优先依据论文，图表或扫描件证据不足时提示补充或 OCR；原文和导入中文不会按相同页码强行配对。选区超过 2,000 字符时请缩小范围。浮动工具栏也保留四色高亮和“添加备注”。“批注”打开侧栏，支持编辑备注、修改颜色、删除记录、点击记录回到对应页面。批注自动保存在本机，随缩放与栏宽调整定位。
4. 需要翻译英文论文时，点击“翻译设置”，填写在线服务的 API 基础地址和密钥，再点击“获取模型”，在下拉框选择特定模型。列表显示模型名称及真实 API ID，选择后自动填入 ID；服务商未提供列表接口时，可手动填写 API 模型 ID。接口需兼容 Chat Completions；地址无需添加 `/chat/completions`。根地址会自动补充 `/v1`，已有自定义路径保持原样。点击“测试连接”后保存；连接测试会发送小请求，服务商可能计费。获取列表本身仅请求 `/models`。
5. 点击“翻译全文”，完成后中文出现在右侧，并自动保存到原文所在文件夹，命名为 `<原文名>.中文译文.pdf`；界面会显示实际保存路径。遇到不同内容的同名文件时使用 ` (2)`、` (3)` 等编号，保留已有文件；同内容直接复用。重新打开已有生成译文的原文，或点击“翻译全文”复用缓存，也会补回缺失的中文副本。原目录无法写入时仍保留已完成译文，并提示点击“另存译文”。处理过程中可继续阅读与批注；完成或取消后才能保存新配置。
6. 拖动中线调整两侧宽度；鼠标位于 PDF 页面时，按住 Ctrl 向上滚动滚轮放大、向下滚动缩小，以鼠标指向的内容为中心，范围为 50%～300%，也可使用栏顶部的缩放下拉框。连续缩放即时预览，停止滚轮后补充清晰画面；滑动页面时始终使用清晰渲染，不切换到低清预览。“联动阅读”开启时按对应页和页内比例同步，两栏一起缩放。关闭后，两侧可独立翻页、滚动和缩放。键盘左右方向键也可调整中线。
7. “另存译文”保存当前显示的中文 PDF，包括导入的版本。批注作为软件内的本地记录单独保存，不改动原 PDF，也不嵌入另存的译文。软件会阻止覆盖当前原文及已配对的两个导入源文件。

0.1.7 修复了连续数字编号的参考文献和列表被合成大段的问题，保留续行、作者、期刊和 CrossRef。拆段依据原 PDF 的行位置与连续编号完成。升级后请点击“翻译全文”重新生成存在排版问题的旧译文；旧 PDF 不会自动改写，新翻译与旧缓存、旧版本批注分别关联。

滚动时使用缓存的页面几何位置及二分定位，位置更新不再逐帧刷新整个应用；画布和文本层按需加载，页组件避免重复渲染，高倍率画布限制约 800 万像素。96 页双栏本机测试的 200 帧往返滚动中，逐页几何读取从 114,624 次降至 0 次，95% 帧间隔由约 23.6 ms 降至约 16.8 ms。该数字是固定测试负载的实测，不代表所有文档与设备恒定帧率。

内置 [科研中英对照 skill](skills/research-bilingual-translation/SKILL.md)。其共享规则实际编译进批量正文、术语提取和单段回退的翻译请求，约束术语一致、否定与结论强度、数字单位、公式占位符、参考文献信息及段落对应。支持在 Codex 中作为 `$research-bilingual-translation` 使用；安装包的 `resources/skills` 也保留完整 skill。规则参考上游 [BabelDOC](https://github.com/funstory-ai/BabelDOC) 和 [PDFMathTranslate-next](https://github.com/PDFMathTranslate/PDFMathTranslate-next/blob/main/docs/en/advanced/advanced.md) 的公开接口，未安装第三方 skill。规范与结构检查不能替代关键内容的人工核对。

0.1.9 新增“保真省钱”策略：DeepSeek 官方接口的正文、单段与术语采用 Low 思考，保留科研规则、上下文及输出预算；发现可检测的缺段、数值或公式异常时，仅将异常条目连同完整上下文升级 High 一次。已通过段落保留；修复后仍不合格明确失败。同任务遇到修复失败或连接中断后不再重复付费，重新启动任务可继续复用成功段落。新配置推荐此模式；旧配置保持原手动档位，可在设置切换。17 条短样本的两组译文经独立核对未发现明显语义错误，新版输出 token 少约 10%、该样本费用少约 1.1%；样本很小，不能证明任意论文质量等价或固定节省。

选择“手动思考档位”仍可使用 Low / High / Max；三档均开启思考。更深思考可能增加费用，不保证译文更准确。其他兼容服务保持原参数，不注入 DeepSeek 专用字段。任务底部按服务商实际响应展示真实请求、输入/输出、思考用量及重点复译次数；输出已经包含思考用量，不重复计费。本地复用独立统计。切换省钱模式时兼容的完整 High 译文与原批注仍可直接复用。

请求启动速率仍由每秒请求数控制；翻译工作线程与 QPS 分离，默认 QPS 2 时最多同时处理 8 个请求。提高并发只能减少排队，实际速度仍受模型思考、服务商限流及 PDF 排版影响。0.1.5 参考 [DeepSeek Harness 的稳定前缀设计](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/session/README.md#model-experience)，将批量正文、术语提取及单段翻译的固定规则前移，变化的术语表与正文后移；相同标题放在批次内容前。本地缓存还会识别 JSON 对象键顺序及排版不同但内容相同的已知批请求，并兼容旧缓存。正文、术语与思考参数保留，不添加历史对话来提高表面命中率。翻译的新正文占比与长对话不同，实际服务端命中率取决于服务商持久化和返回的 usage，不能保证达到特定百分比。

0.1.3 的状态栏还显示“平均输出 xx token/s”及“缓存命中 xx token · xx%”。平均输出速度按已完成且返回输出用量的远端请求计算：总输出 token 除以这些请求各自的完整耗时总和，包含等待及服务商计入的思考用量；并发分别计时，本地缓存和 PDF 解析排版不参与。非流式请求在完整响应返回后更新此值，尚无样本时显示“待统计”。悬停可查看统计口径。

首版支持 Windows 10/11 x64、中英文 PDF 阅读、高亮与文字备注、英文到简体中文翻译。扫描件可以浏览页面，选字批注和翻译需要先进行 OCR；Word、EPUB、离线翻译、手写画笔不在首版范围。原文与译文段落并不保证等高；页数不一致时软件关闭联动。

翻译质量取决于 PDF 文本提取、所选模型与学科术语。图片中的文字可能保留英文，复杂表格、跨栏/跨页内容可能需要人工核对。中文用于辅助理解，关键术语、数字、实验条件、否定与结论请对照原文。模拟测试不代表真实服务的翻译准确度。

## 数据与隐私

- 所选服务商会收到待翻译文本。文件解析、页面显示、译文缓存和阅读记录在本机完成。
- API 密钥使用 Electron safeStorage（Windows DPAPI）加密保存，界面不会读取已保存的密钥。同一服务地址下，获取模型、测试连接和保存时可留空复用已存密钥；更换服务地址需要填写对应密钥。
- 设置与缓存位于 `%APPDATA%/paper-reader`（实际位置可在“翻译设置 → 关于软件与翻译引擎 → 打开本地数据目录”查看）。引擎使用该目录下独立的 `engine-home`，与其他 PDF2ZH 软件的配置和缓存隔离。
- 原文快照、译文缓存位于数据目录。完整译文按文件内容、服务地址、模型、思考档位和引擎版本区分，密钥轮换不使有效译文失效。请求级缓存位于 `engine-home/reader-api-cache`，保留已完成的相同请求以便重试复用；截断、空回复和批翻译漏段结果不写入成功缓存。相同并发请求会合并；更换服务或思考档位不会误用旧请求结果。
- 导入配对保存在 `documents/<英文内容哈希>/pair.json`，两个 PDF 均保留本地快照，无需翻译服务。更换中文文件会使用独立的批注版本；再次打开英文文件时优先恢复导入配对，不随 API 模型变化。显式“翻译全文”会切换当前显示版本，保留导入快照和配对。
- 批注位于数据目录的 `annotations` 子目录；原文批注与不同翻译版本分别关联，修改模型不会把旧译文的高亮错贴到新译文。
- 问答会话位于 `questions`，文本索引位于 `question-index`，问答复用结果位于 `question-cache`，独立用量记录位于 `question-usage.json`。删除问答会话保留论文、原批注和累计用量。问答用量与当前翻译用量分别显示并汇总 token；服务商未完整报告的用量不视为免费。没有配置模型单价时不推算金额。
- 退出程序会终止正在进行的翻译任务。已完成的译文保留；未完成任务可再次打开原文后重试。
- 安装与升级不会删除数据；卸载后也保留本地数据。如需清理，请先退出应用，再在用户数据目录中手动处理。不要将 API 密钥或包含敏感论文的缓存发送给他人。

## 开发与构建

开发机需要 Node.js 24 或更新版本和 Windows x64。

```powershell
npm ci
npm run runtime:prepare
npm run dev
```

`runtime:prepare` 从官方 Release 下载约 630 MiB 的 with-assets 运行包，先验证固定 SHA-256，再解压到 `resources/runtime/pdf2zh`。完整安装包包含该运行包，体积较大是正常情况。

```powershell
npm test
npm run build
npm run test:ui
npm run test:pair
npm run test:zoom
npm run test:settings
node scripts/question-smoke.mjs
npm run test:scroll
npm run test:layout
npm run test:references
npm run package
npm run test:installer
```

安装包输出到 `release/PaperReader-Setup-0.1.11.exe`，解包版位于 `release/win-unpacked`。安装包未签名，Windows 可能显示未知发布者。0.1.4 修正了 ZIP 解压插件无法写入 UTF-8 中文文件名的问题，包内主程序文件名为 `PaperReader.exe`，软件名称与快捷方式仍为中文。0.1.11 将 PDF 栅格绘制移至独立进程，补齐冷页首帧、快速无损编码、图像解压、缓存及取消处理，并修复译文栏横移时的文字拖选。性能数据及验证范围见 [阅读器复验报告](docs/proposals/2026-10-18/03-reader-performance-follow-up.md)。

`test:installer` 从生成的安装包提取原始载荷，调用安装器实际使用的 NSIS ZIP 插件完整解压到独立中文目录，并检查主程序与翻译运行时。测试不会注册应用或修改现有安装，结果与解压文件保留在 `output/installer-smoke`。可传入安装包路径复查旧版本。

`npm test` 验证 PDF 解析、扫描件、中文空格路径、有效译文验证、取消、API 错误、加密配置、缓存、阅读位置映射及批注增删改与并发保存。`test:ui` 用实际 Electron、PDF.js 和官方翻译引擎，连接本机模拟 API 验证翻译、双栏联动、选字批注、单栏阅读和重启恢复；中文阅读用独立的未配置 API 数据目录验证。截图输出到 `output/playwright`。

真实服务翻译效果需要在软件内配置自己的 API 后验收。不能以模拟 API 的结果评估模型翻译质量。

Token 优化支持 `PAPER_READER_TRANSLATION_STRATEGY=baseline|terminology|adaptive`，默认 `baseline`。
`terminology` 在文档、原始提取批次、语境、生成参数、模型与策略相同的条件下复用术语结果；新章节仍按原始批次提取，已知译法仅作为需核对定义的候选。`adaptive` 额外尝试清晰定义术语的非思考模式，并路由风险段落；实验策略进入缓存范围，尚未通过真实质量与费用验收，不默认启用。`PAPER_READER_TRANSLATION_REPLAY=0` 可关闭译文 IL 回放。回放记录保留源映射和原质量报告链接；重新排版不表示重新通过了语义检查。

```powershell
npm run test:replay
npm run experiment:tokens
```

实验默认完全离线，输出 `report.json`、`blind-review.csv`、独立盲评映射和原始 usage 诊断。冷/热表示本地结果缓存状态；服务端命中只使用 provider usage，不保证可制造远端冷态。每组随机顺序并重复三次；热态预备请求单独计量，不能从总预算中扣除。已有实验目录拒绝重复使用，旧缓存不删除。具体范围及真实实验命令见 [Token 优化验收记录](docs/proposals/2026-10-18/01-token-cache-implementation-validation.md)。

`node scripts/question-smoke.mjs` 使用真实 Electron、PDF.js 和本机模拟问答服务，验证选区旁放大镜、词句/中文选区、引用、追问、复制、保存备注、取消、手动重试、版本隔离、删除历史及宽/窄窗口。结果在 `output/playwright/questions`，实施范围和人工评估限制见 [选区问答验收记录](docs/proposals/2026-10-18/02-selection-question-answering-validation.md)。

`test:pair` 使用实际 Electron、PDF.js 与独立的无 API 数据目录，验证选文件导入、双 PDF 拖入、左右交换、页码与缩放联动、不同页数、中文版本批注隔离、错误文件与取消、键盘焦点，以及移走中文源文件后的重启恢复。测试 PDF 明确标为测试材料，截图位于 `output/playwright/pair-*`。

`test:settings` 验证获取模型、展示名与 ID 区分、指定 ID 提交、保存密钥留空复用、切换服务地址、模型列表不受支持时手动配置，以及 HTTP 400 具体错误显示与脱敏。通过 `PAPER_READER_EXECUTABLE` 环境变量也可以对打包程序执行这些界面测试。

`test:scroll` 使用 96 页双栏 PDF，验证页面几何缓存、300 次真实滚轮输入、滚动期间移动鼠标和两栏接管滚动。检查每帧最多绘制一个 PDF 画布，以及联动位置、缩放、窗口变化和高倍率画布内存上限；帧间隔和主线程长任务记录在 `output/playwright/wheel-scroll-after.json`。

可用绝对路径参数 `--data-dir=D:\指定目录` 指定独立的数据目录。命令行也支持将 PDF 路径作为参数传入。开发机缺少 VC++ 运行库时，可运行官方运行包附带的 x64 安装程序；安装程序也会检查该依赖。
