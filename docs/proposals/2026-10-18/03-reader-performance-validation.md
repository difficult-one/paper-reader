# 阅读性能实施与验证记录

日期：2026-10-18。对应方案：`03-reader-performance.md`。

本文前段保留第一轮实现及失败记录。后续修复和最新验收以 [继续修复与复验](03-reader-performance-follow-up.md) 为准；最终程序全部 10 个正确性/性能阶段、正式 0.1.11 安装包提取、一致性核对及提取版回归均已通过。

## 实现与本轮修复

- 两栏共享动态优先级队列：活动栏可见页、另一栏可见页、前向预取、其他任务；等待时间提升；取消信号与 generation 校验。画布启动/续绘、文字层和后台尺寸读取共用队列。
- 调度统计明确计量 dispatch，不能把 PDF.js 再次异步调度后的绘制耗时当作已受 6 ms 硬限制。真实帧间隔、长任务和 Chrome trace 单独采集。
- 栅格缓存默认 128 MiB，低内存档 64 MiB；文字内容 16 MiB，尺寸表 1 MiB。可见、绘制中及选区资源固定；绘制结束或取消后释放画布。缓存键含来源与完整 PDF 指纹，避免保留原始 ID 的译文复用原文文字。
- 原有画面在滚动、缩放和栏宽变化时保留。清晰画布只升级可见页；屏外保留受预算限制的预览。预览单页字节额度为总预算的 1/256，避免 96 页双栏的整篇往返持续淘汰预览。
- 每栏共享可见范围观察器；批注按页索引，未改变页的批注数组保持引用稳定；首屏先读取必要尺寸，完整尺寸表后台补全，修正时恢复页码与页内位置。
- 阅读栏 memo 与稳定回调隔离翻译计时、日志及问答状态更新。
- 活动选区同时由实时浏览器 Range 和拖选状态保护。文字层复制旋转属性及 PDF.js 必需的尺寸变量；原生拖选期间冻结文字层缩放，松手后再应用，避免 Blink 重置拖选起点。

## 测试方法与文件

长测命令：

```powershell
node scripts/scroll-smoke.mjs --release --cache-mib=64 --label=performance-final-64mib-unthrottled
```

每轮 60 秒 × 3，另加 600 秒往返。每轮从第一页开始，原生滚轮到达最后一页底部才反向，回到顶部才再次向下；每 10 秒切换两栏接管，保存端点位置和到达次数。冷页跳转、持续输入、停止后的清晰层补全分别保存原始数据。20 次/秒为输入负载有效性下限。

Windows 测试窗口遮挡会使 Chromium 降低输入/合成速率。本测试进程显式关闭背景/遮挡限速，环境文件保存启动参数；先前低负载和局部反向的记录保留为诊断资料，不计为发布通过。原始坏帧未删除。

文字与低内存回归命令：

```powershell
node scripts/reader-selection-smoke.mjs
```

该脚本在独立测试数据目录生成原始 ID 相同、修改 ID 与内容不同的 300 页双栏 PDF，包含 0/90/180/270 度页面，DPR 2、64 MiB 缓存、50%/100%/125%/250%/300% 缩放；验证跨页选区经过远距离跳转及缓存回收仍保留、缩放后文字层恢复、真实鼠标拖选及高亮批注。

结果文件：

- `output/playwright/performance-final-64mib-unthrottled/environment.json`：硬件、GPU、DPR、窗口、刷新率与启动参数。
- 同目录 `round-1/2/3.json`、`soak.json`、`summary.json`：门禁汇总。
- 同目录 `*.raw.json`、`*.cold.raw.json`、`*.settlement.raw.json`：完整时序、页面、缓存及进程内存采样。
- `output/playwright/reader-selection-64mib/result.json` 和 `failure.png`：最终文字/低内存结果，以及右栏剩余边界的截图；`selection-annotated.png` 为此前仅覆盖原文栏的一轮截图。
- `output/playwright/performance-final-trace/round-1.trace.json`、`.cpuprofile`、`analysis.json`：最终策略的补充 30 秒诊断录制。
- `output/playwright/performance-trace-after/round-1.trace.json`、`.cpuprofile`：修改前一版策略的诊断 trace；不能代替最终版长测结果。

## 结果解释

本机为 Ryzen 9 9955HX、32 GB 内存，双屏报告 300/240 Hz，阅读窗口 DPR 1.5。长测使用方案中的 60 Hz 暂定数值作回归门禁；即使通过，也不能据此宣称本机 300 Hz 流畅或完成真实 60 Hz 参考机复验。GPU 环境原样保存在 JSON 中，不据显示名称推断实际硬件加速路径。

最终数值与未达标项目以完成后的 `summary.json` 和本文后续实测表为准。测试中遇到的超标样本均保留；门禁失败会返回非零状态。64 MiB 是栅格缓存预算，不代表总进程 RSS。

栅格额度包括显示中和绘制中的画布，按宽 × 高 × 4 字节计算。文字内容按 JSON 字符数 × 2、尺寸表按页数 × 32 字节估算容量；这些估算不等于 JS 对象或 DOM 的精确堆占用。

尚需另外验证的范围：用户问题机器与问题 PDF、真实安装包、真实 60/120 Hz 设备、触控板、同时真实翻译/问答负载、完整扫描/复杂矢量/大量批注组合矩阵。脚本已提供夹具、页数、DPR、缩放、单栏和安装版可执行路径参数。

## 前一轮长测数值（修复前，保留原始失败证据）

96 页既有论文夹具，双栏，DPR 1.5，64 MiB 档。三轮 60 秒后，再连续往返 600 秒。每一帧和每一个超标样本均保留。

| 阶段 | 帧数 | P95 / P99 帧间隔 ms | 输入反馈 P95 ms | >50 ms 帧 | >100 ms 帧 | 冷页预览 P95 ms | 顶 / 底次数 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 60 秒第 1 轮 | 16,022 | 3.6 / 16.7 | 15.5 | 7（0.044%） | 0 | 52.5 | 5 / 5 |
| 60 秒第 2 轮 | 16,725 | 3.5 / 10.1 | 12.8 | 6（0.036%） | 1 | 无冷页样本 | 5 / 5 |
| 60 秒第 3 轮 | 15,230 | 6.6 / 20.0 | 16.4 | 14（0.092%） | 8 | 633.4 | 4 / 5 |
| 10 分钟往返 | 174,313 | 3.5 / 6.7 | 11.8 | 16（0.009%） | 10 | 348.4 | 55 / 56 |

10 分钟阶段收到 84,619 次原生滚轮输入。峰值栅格占用 **63.97 MiB / 64 MiB**。渲染进程预热稳定窗口的工作集中位数从 1,306.47 MiB 到 1,391.45 MiB，增加 **6.50%**；各 Electron 进程工作集之和从 1,765.02 MiB 到 1,905.95 MiB，增加 **7.98%**（共享页可能重复计入）。增长均低于方案的 10% 门槛，但绝对占用仍高，不能据此宣称已支持真实低内存机器。

通过的性能项：暂定 P95 ≤20 ms、P99 ≤33.4 ms、>50 ms 帧占比 ≤0.1%、输入反馈 P95 <50 ms、缓存容量、预热后的内存增长、整篇到底再回顶以及两栏轮流接管。

**性能门禁没有全部通过。** 仍记录到 19 个 >100 ms 帧，最慢 520 ms；10 分钟阶段还出现一个 128 ms 长任务。冷页预览在第 3 轮与长测中超过 150 ms。没有删除或推定这些帧来自系统，需继续根据最终 trace 定位。冷页样本量较少，不能用其他轮的已缓存页面稀释该结果。

长测脚本旧版本在停止时没有立即刷新已就绪画布的计时样本，10 分钟记录显示 `settled=true`（全部可见页的直接 DOM 就绪检查通过），但 `incompleteClear=4`、`clearP95Ms=null`；该段采样窗口仅约 7.3 ms，早于下一次 50 ms 轮询。现已在观察器回调和停止采样时同步刷新。原始记录保留，这条旧的计时缺失不能解读成四页实际未完成，也不能用作清晰页 P95 达标证据。

修正后的采样器追加 30 秒 trace 复测：`settled=true`、`incompleteClear=0`，清晰层 P95 179 ms，冷页预览 P95 81.3 ms。该轮包含 profiler/trace 开销，>50 ms 帧为 7/6,958（略高于 0.1%，门禁仍返回失败），未用于替换长测指标。Trace 可见约 33 ms 的 Major GC 及约 35 ms 的动画帧回调，但本轮最长帧 83.2 ms，没有复现长测的 >100 ms 停顿，仍不能给超长帧作确定归因。

## 文字正确性与剩余边界

构建通过，35 个测试文件、362 项单元测试通过。真实 Electron 选区脚本确认：原译文缓存隔离；四种旋转方向的文字层边界；跨页 Range 经过 300 页远距离往返及缓存压力仍保留；缩放保留选区并在清除后恢复精确层；DPR 2、300% 连续缩放不超过栅格预算；原文栏在拖选时改变栏宽仍能保存高亮；译文栏普通鼠标拖选正常。

默认并发的一次最终复跑遇到 Windows 测试 worker 异常退出（`3221226505`，`economy-gateway.test.ts`），不是断言失败。随后使用 `npx vitest run --maxWorkers=4`，35 个文件、362 项全部通过。两次日志分别保存在 `output/playwright/reader-performance-unit-tests.txt` 与 `reader-performance-unit-tests-final.txt`，未将异常退出计作通过。

**文字回归也没有全部通过：** 在译文栏按住鼠标拖选的同时，令中线从 45% 改到 55%，整栏向右移动约 139 px，随后继续移动鼠标，仍能复现选区折叠为光标。文字节点保持连接，冻结文字缩放可修复原文栏，但不能覆盖整栏横向平移。该复现由 `scripts/reader-selection-smoke.mjs` 保留，脚本返回失败；仍需在布局协调层解决这一边界，不能声称选区回归全部关闭。
