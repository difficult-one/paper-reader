# 科研论文翻译 skill 改进方案

日期：2026-10-18。结论：**有改进空间。重点是让规则与软件实际执行一致，并建立术语证据、语义风险复核和可追溯报告；不宜继续无差别加长每次调用的提示词。**

## 1. 现有能力应保留

已检查项目 `skills/research-bilingual-translation/SKILL.md`、`references/translation-rules.txt`、`references/review-examples.md`，并对照 `translation-prompts.ts`、`translation-quality.ts` 和 `cache-versions.ts`。

当前规则已经覆盖：科研忠实性、否定和结论强度、术语一致、数字单位、公式占位符、引用、段落对应、参考文献，以及将论文中的指令视为资料。项目规则被编译进真实请求，而不只是放在文件里。这些是现成基础，不需要推倒重写。

## 2. 具体缺口

| 缺口 | 当前证据 | 应如何改 |
| --- | --- | --- |
| 任务规则未细分 | `pair()` 给正文、单段、术语模板都追加完整 researchRules | 公共核心 + 正文/术语任务规则，降低无关指令负担 |
| “两次复核”容易被误读成软件已经执行两次检查 | SKILL 有两次复核要求，软件质量函数主要做占位符与数字检查 | 区分翻译自检、程序结构检查、独立语义复核与人工复核 |
| 数字检查不能确认完整语义 | `qualityParagraph = validParagraph && faithfulNumbers` | 增加限定条件、否定、关系和变量绑定的风险评测/复核 |
| 一致术语缺少可追溯语境规范 | 规则要求一致，但未定义定义出处和歧义冲突状态 | 文档级带定义依据的术语表及版本 |
| 不确定内容的单独报告缺少执行闭环 | SKILL 要求核对说明独立输出，正文 JSON 又禁止说明 | 新增独立 QA 报告通路，不混入译文 schema |
| 版本说明与实际代码有偏差 | SKILL 写更新 `ENGINE_VERSION`；当前已有 translation/layout 双版本与规则 hash | 改为准确描述策略、模板、解析、排版、评测各版本作用 |
| 示例覆盖较少 | review-examples 仅少量代表案例 | 建立按错误类型组织的冻结评测集 |

现有数字检查把数值声明排序比较，能发现许多数值变化，但不能证明“同一数值仍绑定同一变量/组别”，例如交换实验组与对照组的数值而保持数字集合不变。不能把它命名为“语义完全保真”。

## 3. 方案比较与选择

| 方案 | 好处 | 代价 | 建议 |
| --- | --- | --- | --- |
| 只扩充 SKILL.md | 快速、人工工作说明更完整 | 软件不会自动执行新步骤，难证明收益 | 可做文档修正，不能当完整优化 |
| 所有段落额外双模型复译 | 可能发现部分错误 | 费用/延迟显著增加，模型也会共同犯错 | 不默认启用 |
| 规则分层 + 确定性检查 + 风险复核 + 抽样盲评 | 兼顾费用、可追溯性与质量 | 需要代码接入与评测 | 推荐 |

## 4. 建议的 skill 组织

在保持现有项目目录作为维护源的前提下，建议演进为：

```text
research-bilingual-translation/
  SKILL.md                         # 人工作业与软件接入流程、真实能力边界
  references/
    translation-rules.txt          # 公共核心，保持兼容入口
    body-rules.txt                 # 正文忠实性与段落契约
    terminology-rules.txt          # 定义、歧义、缩写和术语 schema
    review-rules.md                # 复核步骤、等级与错误分类
    glossary-schema.md             # 术语、定义出处、作用域、版本与冲突
    quality-report-schema.md       # 位置、问题、证据、状态、复核来源
    review-examples.md             # 便于阅读的例子
    sources.md                     # 原始接口来源和核实日期
  evals/
    cases.jsonl                    # 固定源文与可验证约束
    rubric.md                      # 人工盲评准则、严重性与发布门槛
```

这是建议结构，不要求模型每次把所有文件都读入提示词。应用按任务编译需要的规则；评测、工作流和长示例留在维护侧。对每种模板快照实际发送的规则，确保拆分后必要约束没有丢失。

## 5. 改进后的翻译流程

### 第一步：提取检查

识别文本型/扫描件、语言、双栏阅读顺序、页眉页脚、参考文献、公式占位符与图中文字可提取程度。保存每个源段的 ID、页码、章节、几何锚点和提取版本。

对于跨栏、断词、跨页续段，先在本地恢复结构再翻译；无法可靠恢复时标记该位置。不能通过让模型猜测来掩盖提取错误。

### 第二步：术语表

术语记录至少包含英文、首选译法、原文定义片段、页码、章节作用域、缩写、状态和术语表版本。区分“用户指定”“原文明确定义”“候选待确认”。

不根据模型自报 confidence 就判定可靠。同一缩写不同章节可能另有定义；同一英文词的日常与专业含义不强行统一。用户词表优先，但与原文定义明显冲突时生成报告，不能悄悄修改用户词表。

术语增量提取与去重按费用方案实施。不能缓存模型推断作为“原文定义”，也不能跨文档无条件复用术语。

### 第三步：翻译与确定性校验

按稳定段落/章节边界组织批次，输入中保留必要邻段、标题和术语上下文。输出保持原有 ID→output 契约，只返回译文。

检查条目数、重复/缺失 ID、空译文、公式/标签结构、数值/范围/比较符、单位及引用。进一步加入参考文献条目编号和 DOI/URL 保留检查；允许排版等价变化，但不允许补造来源。

仅局部修复错误项且保留上下文。格式截断、无法可靠解析时不能把猜测的部分输出当作已成功结果。

### 第四步：风险语义复核

采用规则识别候选风险，而不是认为关键词匹配可以证明译文正确。优先覆盖：

- 否定与作用域：not、unless、except、双重否定。
- 条件与逻辑：充分/必要、only if、assuming、有界/收敛/稳定。
- 证据强度：may、suggest、association、因果、相关、不显著与等效。
- 统计含义：百分比/百分点、置信区间、非劣效、样本量、比较对象。
- 变量绑定：相同数字对应哪个组别、量纲大小写、上下标、公式前提。
- 方法限制：适用范围、实验条件、失败案例与作者保留意见。

高风险段可独立复核；低风险段仍抽样，避免只检查有关键词的句子。复核输出结构化问题和源文依据；若无证据不能为了“找错”改写合格译文。High 复核不是正确性保证。

### 第五步：独立报告与版面检查

报告条目建议：`documentId、sourceVersion、paragraphId、page、category、severity、sourceQuote、translationQuote、issue、status、reviewMethod、ruleVersion`。

状态区分：结构检查通过、语义待核对、模型复核通过、人工复核通过、未解决。只有对应检查真的发生才能展示通过状态。

低置信或无法提取内容在报告中显示，不在论文正文插入“模型认为”等解释。报告可以定位到源段；若要复核生成 PDF，检查文字是否溢出、公式是否遮挡、编号是否粘连、段落是否遗漏以及参考文献是否合并。

提示词自检不能发现所有排版错误，PDF 生成后的检查必须是独立步骤。自动检查失败的页面提供缩略图和定位，必要时人工核对。

## 6. 与问答模块共用什么

可共用带页码和定义来源的文档索引、术语表、段落锚点与版本。翻译缓存与问答缓存必须分开。

翻译正文忠实表达原文，不增加解释；问答允许解释，但明确论文依据和背景知识。问答中的新说法不能未经用户确认回写为术语标准，也不能偷偷修改已生成译文。

## 7. 版本和缓存策略

当前 `TRANSLATION_POLICY_VERSION` 已包含共享规则 hash，`LAYOUT_VERSION` 已独立；`library.ts` 的 `ENGINE_VERSION` 是排版版本别名。建议修正 SKILL.md 的旧说明，避免开发者只改别名而漏掉真实缓存依赖。

拆分规则后，策略指纹应包含实际编译的公共/任务规则、模板 schema 和路由策略版本；仅 hash 旧的一个 txt 将不再足够。提取算法和段落边界版本同样进入相关中间缓存键。

- 改译法或保真规则：使受影响翻译结果按策略失效，不覆盖旧版本。
- 仅改布局：优先复用语义中间结果重新排版；如果引擎回放不支持，明确存在重译成本，不能承诺零费用重排。
- 仅改展示文案/人工说明：若未改变实际翻译契约，不应让所有译文缓存失效。
- 改评测标准：对旧结果标注未按新标准复核，可再验证，不自动清空所有结果。
- 批注继续绑定具体 PDF 版本，保留旧文件到新文件的可追踪关系。

项目副本为维护源，打包时校验实际携带的规则指纹；全局 skill 副本与安装包副本记录来源版本，避免三份规则悄悄分叉。本次只写方案，不直接改动任何副本。

## 8. 验收与投入

先以现有 17 条样本作回归起点，再扩展至少 200 段、10 篇、3 个学科；包含本次没有暴露错误的反例，如“交换组别但数字集合相同”。冻结源文和人工约束，允许多个正确译法，不做整句字符串匹配。

| 维度 | 建议发布门槛 |
| --- | --- |
| 结构/占位符 | 发布测试集 100% 通过，故意损坏样本均被拦截 |
| 语义 | 抽查不得新增严重错误；一般错误率不高于原策略，报告分母与样本局限 |
| 术语 | 按作用域评估一致性，不能靠统一成错误译法得高分 |
| 报告 | 每条问题有真实段落定位，已复核状态与执行日志相符 |
| 版面 | 复杂公式、参考文献、跨栏样例无新增漏段、粘连和遮挡 |
| 经济性 | 复核与修复全部计入费用，与第一份方案共用账本 |

预计文档、报告和扩展评测部分约 2–4 人日；任务提示词拆分、术语增量与模型路由计入费用优化工作包，避免重复计费。第一步先修正版本和复核说明，然后用实验逐项引入规则拆分和风险复核。

**最值得改进的不是把 skill 写得更长，而是让“如何发现错误、何时复核、核对过哪里、改动后缓存怎么办”都可执行、可验证。**
