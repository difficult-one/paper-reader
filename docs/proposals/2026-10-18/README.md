# 论文阅读器四项改进方案

日期：2026-10-18。对象：本地 `paper-reader` 0.1.10 源码。交付范围：方案与证据分析，不修改软件、不调用付费翻译、不安装新技能。

## 建议决策

| 事项 | 推荐方案 | 关键判断 |
| --- | --- | --- |
| Token 与费用 | 保留现有直接 API 翻译链路，优先优化术语提取和思考输出，继续完善结果复用 | 不建议为了 95% 命中率迁入 Harness；高命中率不是低总费用的充分条件 |
| 划词提问 | 在现有选字工具栏增加“提问”，用侧栏展示有论文出处的回答 | 用户已确认论文内问答优先；证据不足时明确说明 |
| 连续滚动 | 扩展现有共享渲染调度，加入可见区域优先级、文本层调度、资源预算和性能门禁 | 已有优化有效，但现有测试不能证明复杂论文连续滚动无卡顿 |
| 论文翻译 skill | 保留核心保真规则，分离任务规则、风险复核与质量报告，并修正文档中的版本说明 | 结构检查不等于语义正确，skill 文字也不等于软件实际执行了复核 |

## 实施顺序与投入

先建立费用和性能基线，再做翻译费用改进与渲染治理，随后加入划词问答；skill 的版本规范与评测集可先行，涉及提示词的调整与费用实验同步验证。

| 工作包 | 初步估算（熟悉本项目的单人开发，人日） | 依赖 |
| --- | ---: | --- |
| 费用统计、术语增量化、按风险路由、小规模评测 | 4–7 | 现有网关与缓存；包含基本规则拆分 |
| 连续滚动诊断、调度与资源治理、性能回归 | 5–8 | 真实问题 PDF、基准设备与安装版复现 |
| 论文内划词问答 MVP | 5–8 | 稳定的选区、后台文本索引、费用与请求调度 |
| skill 文档、独立质量报告、扩展语义评测 | 2–4 | 与费用工作包共享的规则拆分不重复计入 |

合计约 16–27 人日，属于方案估算，不是报价或工期承诺；复杂 PDF、原文/译文精确映射、第三方接口差异可能增加投入。性能门槛未达标时不应强行按日期发布。

## 证据与边界

- 本次检查了翻译网关、缓存、质量校验、PDF 渲染、选区、IPC、项目 skill、既有实验和滚动结果。
- 重新聚合了历史 189 条请求的 usage；该数据不是当前用户全部用量，也不是 0.1.10 的新实验。
- 滚动结论来自源码与既有结果文件；本次未重新运行应用进行性能录制，不把静态分析中的风险称为已确认的全部根因。
- DeepSeek 定价、缓存规则及 Harness 身份参考官方在线资料，访问日期为 2026-10-18；正式实施时需重新核实模型版本和价格。
- 用户已确认比较对象是官方 `deepseek-ai/deepseek-harness`，问答先依据论文内容。
- 本地目录没有 Git 元数据，方案以文件形式交付，无提交记录。
