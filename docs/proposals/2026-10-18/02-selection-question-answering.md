# 选中文字提问模块方案

日期：2026-10-18。用户已确认：**论文内问答优先，证据不足时明确说明**。推荐复用当前选区与批注交互，增加“提问”入口和独立问答侧栏。

## 1. 使用体验

读者在英文或中文论文中选中术语、句子或短段落，浮动工具栏保留已有高亮/备注，并增加“提问”。点击后冻结选区快照，打开右侧问答栏，显示选中文本、所属版本和页码。

提供三个快捷问题：“解释术语”“解释这句话”“在本文中有什么作用”；也可输入自定义问题。仅选中文字不会发送请求，点击快捷问题或发送才调用模型。

回答默认包含：简短直接解释、本文语境、可点击的论文出处。需要补充一般知识时标明“背景解释”，不得把它写成作者结论。若缺少定义或图表证据，提示“当前论文可提取内容不足以确认”，同时指出缺少哪部分。

可继续追问、停止生成、复制回答、将回答保存为备注；保存备注是用户显式动作，不自动覆盖原批注。默认回答约 150–300 中文字，复杂问题可展开；长度是偏好，不能截断关键限定条件。

## 2. 交互方案比较

| 方案 | 优点 | 代价 | 决策 |
| --- | --- | --- | --- |
| 小型浮层直接显示回答 | 入口近 | 长回答遮挡正文，追问与引用难容纳 | 不作主方案 |
| 选区入口 + 右侧可收起侧栏 | 能追问和回看出处，复用批注区域习惯 | 需控制栏宽和 PDF 重排 | 推荐 |
| 独立聊天窗口 | 容量充足 | 脱离原文，窗口与文档绑定复杂 | 后续需求明确再做 |

侧栏建议与“批注”共用辅助区标签，一次只展开一个面板。沿用当前字体、配色和控件；不重做阅读器视觉系统。宽窗口使用约 340–420 px 侧栏，窄窗口使用可收起覆盖抽屉，保证至少一个 PDF 阅读栏仍可用。

打开/关闭侧栏只提交一次阅读区域宽度变化，不做逐帧宽度动画触发 PDF 重绘。关闭后恢复焦点和原阅读锚点。

## 3. 现有基础与新增模块

当前 `PdfPane.tsx` 已输出 `quote + anchors + x/y`；`App.tsx` 已补充 `sourceKey/documentId`；`selection.ts` 将高亮坐标归一化。因此无需新建一套文字选择系统。

| 层 | 推荐变更 | 作用 |
| --- | --- | --- |
| 选区与入口 | 扩展 `SelectionToolbar`；保留选区快照 | 避免点击输入框后选区消失 |
| UI | 新增 `QuestionPanel.tsx` 与局部会话状态 | 流式展示、追问、停止、引用跳转 |
| 类型与 IPC | 扩展 `src/shared/types.ts`、`src/preload/index.ts` 和主进程 handler | 请求、取消、增量事件、历史查询 |
| 文档上下文 | 新增 `document-context.ts` | 后台提取段落、建立页码/原文锚点与检索索引 |
| 问答服务 | 新增 `question-service.ts` | 组装证据、调用服务、校验引用、持久化 |
| 模型调用 | 抽取可复用 provider transport/限流/usage 代码 | 复用连接与密钥管理，避免经过翻译 schema 重写 |

上述新增文件名为建议，不表示已经实现。问答不要直接复用会强制翻译模板、强制单一输出或使用翻译缓存键的入口。

## 4. 数据流与上下文

```text
选区快照 → 主进程校验文档及版本 → 取得当前段落和邻段
        → 检索术语定义/相关段落 → 构建证据包
        → 模型回答流 → 校验引用 → 展示并保存会话
```

### 文档索引

- 本机后台提取文本；优先利用引擎已有段落与几何信息，无法复用时做一次后台 PDF 文本提取。不能把 textLayer 的 DOM 顺序直接当成双栏论文阅读顺序。
- 每段存 `documentHash、sourceVersion、page、paragraphId、text、rects、section`。页码首先使用 PDF 物理页号，印刷页码只有可靠映射时显示。
- 默认以选区所在段和邻段为基础，使用本地关键词/BM25 类检索查找缩写定义与重复术语；第一版不必引入向量数据库或额外 embedding 费用。
- 初始预算建议：选区最多约 2,000 字符、邻段和检索片段共约 4,000–8,000 token；按真实 tokenizer 和模型限制调整。超长选择让用户缩小范围或明确分段，不静默截掉关键内容。
- 历史最多保留最近数轮相关问答，较早内容可摘要；论文事实的依据始终来自原文片段，不把历史模型回答当证据。

### 中英文与导入配对

原文与译文不保证逐段对应，导入的中英 PDF 更不能依靠相同页码判断同一段。生成译文应逐步保存 source↔target 段落映射；没有可靠映射时，只引用所选版本，明确“依据中文版本”，必要时检索英文原文匹配，无法确认则不伪造英文出处。

扫描件无文字层时给出“需要 OCR”的明确状态；首版不自动将整页图片上传服务。公式、图中文字无法可靠提取时标记证据缺口。

## 5. 回答与引用契约

每次发送的证据使用受控 ID，如 `S1/S2`，由主进程保存 ID 到文档页码与段落的映射。模型只可引用这些 ID；UI 将其转换为“原文第 4 页”链接。拒绝未知 ID，不允许模型自由生成一个页码就被当作已核实出处。

流式阶段可以显示正文，但引用在校验后才可点击。回答需要区分“论文明确陈述”“根据论文推断”“背景知识”；无支持时不能制造权威语气。模型能引用真实片段也不保证推论成立，仍需评测引用是否支持结论。

论文与用户选区作为资料传入，里面的“忽略规则”“执行命令”等文字不改变系统任务。首版问答无文件操作或命令工具，不具备通过论文内容执行外部动作的能力。

## 6. 接口、隔离和费用

请求建议字段：`requestId、documentId、sourceVersion、selectionSnapshot、question、conversationId`。服务端根据已打开文档解析正文，渲染进程不提供任意文件读取路径。

事件建议：`started / delta / completed / failed / cancelled`，每条附带请求、文档及会话 ID 和序号。切文档时取消原请求或留在原会话后台，不能将旧响应展示到新论文。

- API 密钥留在主进程，沿用加密保存；配置缺失时引导至现有设置。
- 默认沿用用户已选服务和模型，问答策略独立于翻译策略；不暗中改换服务商。
- 翻译与问答共用服务级 QPS/并发预算，问答具有交互优先级但不能饿死翻译；第一版限制单会话一个在途请求。
- 流式增量约每 30–50 ms 合并刷新局部组件，不把每个 token 写入全局 `App` 状态。网络取消向上游传播，但已经生成的 token 仍可能计费。
- 问答结果缓存按文档、版本、证据、问题、模型和规则版本区分；追问还需包含会话上下文。不得仅按术语拼写全局复用。
- 首次发送说明将发送选区及相关论文片段到已配置服务；不默认上传整篇、也不自动联网检索。
- 会话存本机，可按文档查看、删除；删除问答历史不删除论文和原批注。usage 与翻译分别展示并计入总费用。

## 7. 状态与可访问性

必须覆盖：无选区、扫描件、索引构建中、配置缺失、发送中、部分回答、完成、停止、超时、429、证据不足、文档切换。重试必须保留问题并显式触发，避免后台重复扣费。

支持键盘选择后进入提问、Enter 发送/Shift+Enter 换行、Esc 收起与焦点恢复；生成状态通过可访问提示报告，不能每个 token 都朗读。面板滚动不应带动 PDF 或吞掉 PDF 滚轮。

## 8. 验收与分期

第一期约 5–8 人日：英文/中文选区、论文局部检索、流式问答、可信出处跳转、取消与错误态、本机会话。第二期才考虑跨章节检索增强、术语卡片、可靠的双语段落映射；联网检索本次不做。

建议验收集不少于 100 个问题，包含多义词、缩写、跨页定义、表格依赖和不可回答问题：

- 选区快照与页码/版本绑定测试全部通过，未知引用 ID 拦截率 100%。
- 人工评估回答正确且有支持出处的比例目标 ≥90%，引用支持率目标 ≥95%；无法回答的样本必须明确表达不足，不用该比例保证任意专业领域正确。
- 侧栏打开本地响应 P95 <100 ms；网络首字延迟另计并显示，不承诺由客户端保证。
- 问答生成期间重复执行滚动验收，指标不得明显退化；停止、重试和切换文档不串会话、不重复自动收费。
