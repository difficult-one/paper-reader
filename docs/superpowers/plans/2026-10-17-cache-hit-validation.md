# 缓存修复实施与验证记录

日期：2026-10-17。应用版本：0.1.8。

本记录对应 `2026-10-17-cache-hit-optimization.md`，主体为 0.1.8 发布时的离线验证。后续用户授权三篇论文、总预算 ¥10 的真实对照；完成六次完整翻译后，用户停止缓存研究并改为“省钱且质量高”。原实验的 224 个已确认请求费用为 ¥2.68808856，8 个中断请求仍按上限保留，不能作为完整三篇配对结论。新方向及样本验证见 `2026-10-17-fidelity-economy.md` 与 `output/fidelity-economy-validation/保真省钱验证报告.md`。

## 已实施的行为

1. 请求级计量：每次上游尝试分别保存 H、M、P、输出和思考用量、缺失状态、异常、HTTP 状态与耗时。数值异常仍留在 raw 字段；由 P-H 推算的 M 单独记录。
2. 统计口径：只在同一批可计算样本上计算 ΣH/(ΣH+ΣM)。界面显示 miss、样本覆盖率、推算和异常；本地复用不返回伪造的服务商 usage，也不参与服务端命中率。
3. 前缀诊断：按模板分组，保存规则、上下文、术语与固定区指纹、固定区字节数、同组相邻请求首个变化字节。新固定前缀单独标记本地冷观察，并汇总冷阶段之外的样本。
4. 稳定前缀：沿用已有批量及术语模板分离，只修复单段回退中术语位于标题之前的问题；带额外协议字段的消息保持原样。没有添加无用前缀、历史、额外术语提取或付费预热。
5. 实验冷启动调度：同组最初两个真实请求有界串行；有效命中证据可提前解除限制。实际发送处保留 QPS 节奏，取消和错误释放等待。默认关闭；仅在受控实验中用进程环境变量 `PAPER_READER_CACHE_COLD_START=1` 启用。尚无真实成本收益依据，不作为默认优化启用。
6. 段落缓存：独立的 `paragraph-v2` 命名空间。键覆盖论文身份、服务、模型、思考档位、策略、完整有序源批次上下文、段落位置、标题、术语、请求参数、正文、占位符及元数据，仅排除临时返回映射 ID。
7. 部分恢复：只请求未确认的段落，同时把完整原始源批次作为只读上下文保留，按原 ID 和顺序合并。缺段响应中的有效段落独立保存；截断、重复 ID、空译文、错误占位符及样式层级变化不进入成功缓存。合法完整样式片段可以随中文语序移动。
8. 版本分离：PDF 键同时包含翻译策略和排版版本；请求、段落缓存只包含翻译策略。科研规则文件内容参与策略指纹。兼容旧研究规范的完整 PDF 使用受限只读回退，并保留旧批注版本标识。

段落边界不意味着邻段没有语义影响。因此，更换邻段、源批次顺序或上下文时保守失效。例如，同篇论文同标题下，河流语境中的 bank 译文不会用于银行语境。不能保证任意拆分、合并批次后都复用。

## 离线基线对照

对照使用本次修改前的源码备份与当前网关、同一个本地模拟服务、同一模型参数、相同的两个有序源段落，连续处理三次，仅更换临时段落 ID。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 逻辑批次 | 3 | 3 |
| 实际上游请求 | 3 | 1 |
| 远端待翻译段落单元 | 6 | 2 |
| 完全本地复用请求 | 0 | 2 |
| 本地段落复用 | 0 | 4 |

原始结果：`output/cache-optimization-validation/comparison.json`。当前版本的请求日志和汇总：同目录 `offline-after.jsonl`、`offline-after.summary.json`。

模拟服务刻意对每次远端请求返回固定 P=100、H=64、M=36、输出=30，用于验证计量和隔离。两组服务端比例均为 64%；这些 token 不代表真实分词、真实账单或 DeepSeek 命中率。毫秒级本地耗时也不代表在线速度。

- 当前 `npm test`：123 项单测通过，覆盖缺失/异常 usage、加权分母、重试、日志隐私/失败/轮转、模板、冷启动/QPS/取消、段落上下文隔离/并发/损坏响应、版本失效、旧数据与批注。并发诊断按实际发送顺序记录，正文中的输入标记不影响部分恢复状态。
- `npm run build`：TypeScript 检查及 Electron 主进程、预加载、界面构建通过。
- 初次 `npm run test:ui`：真实 BabelDOC 引擎连接本地模拟服务，三类模板、翻译显示、批注、导出、重启恢复和中文独立阅读通过。
- 增强版 `npm run test:ui`：三类实际模板、缺失样本下的 60% 模拟比例、诊断隐私、真实子进程取消后重试、重启完整 PDF 零新增请求通过。增加的等待辅助函数会等待异步桥接条件，避免将 Promise 本身当作已满足条件。
- 独立审查发现的上下文误复用、样式片段语序、调度释放后 QPS 突发均已先复现再修复；复查无剩余可操作问题。

打包版已从实际 NSIS 安装包解压至独立中文目录，重复通过上述增强版界面、取消重试与重启缓存检查。6 项真实 BabelDOC/Python 排版检查也通过。最终安装包及哈希见 `release/0.1.8-验证记录.md`。

本机 Node v24.15.0/Vitest 在开发验证中出现过两次测试工作进程原生异常退出（3221226505），无 JavaScript 断言或堆栈可归因；同命令重跑通过。保留该环境现象，不将异常退出那两次计作通过。

## 本机诊断文件

翻译设置 → 打开本地数据目录 → `engine-home/cache-diagnostics`。

- `<任务ID>.jsonl`：每次实际远端尝试和本地复用事件。
- `<任务ID>.summary.json`：分模板汇总、可计算/缺失/异常样本、热阶段 H/M、原始字段覆盖率、日志写入完整性与耗时。
- 保留最近 30 个任务。单个请求日志按约 8 MiB 软上限保留当前文件及两份轮转文件；汇总覆盖整个任务。日志写入失败不使有效翻译失败，界面与汇总记录缺失。

日志不保存密钥、论文正文、完整提示词或回复。模型标识使用受限格式标签及指纹；其他上下文仅保存指纹、类别、长度和变化位置。现有翻译缓存仍需保存译文本身，与诊断日志分开。

完整请求缓存使用规范化请求、论文身份、服务/模型、思考档位及策略版本作为键。引擎不会把缺少论文身份的旧请求记录自动升级为新策略命中；旧文件保留，无论文范围的兼容调用仍支持原有只读回退。旧完整 PDF 的兼容回退另由旧版本标识和精确科研规则指纹限制，不改变其批注关联。

## 后续真实 DeepSeek 对照

用户只需确定论文路径/页码范围与人民币费用上限。助手负责读取本机配置、运行、收集日志和生成对照报告，不需要用户手工抓取 API 响应。

执行时保持同一论文、服务、账号、模型、思考档位、输出预算与科研规则。使用独立本地缓存目录隔离新旧实现，记录 A/B 顺序、冷/热观察和源文件指纹；交替顺序并重复，避免把前组建立的服务端缓存全部算成后组收益。

报告请求/失败/缺失数量、原始与推算 H/M、分母覆盖率、输出及思考 token、各模板与热阶段比例、本地复用、总耗时和冷启动等待；按测试当时的官方价格估算费用，输出已含思考时不重复计费。超时或无 usage 的尝试费用保持未知。

DeepSeek 官方依据（2026-10-17 核对）：[缓存机制及 H/M 字段](https://api-docs.deepseek.com/guides/kv_cache/)、[Chat Completions 用量定义](https://api-docs.deepseek.com/api/create-chat-completion/)。没有可依赖的客户端清缓存开关，不保证第二个或第三个请求必定命中。未完成真实对照前，不宣称提高了特定命中百分比或降低了实际费用。

## 升级及回退

安装 0.1.8 前退出旧程序，并备份“打开本地数据目录”所指目录。安装过程不删除旧 PDF、导入配对、批注和阅读记录；新缓存使用独立版本及命名空间，不覆盖旧译文。

回退时退出程序，使用保留的 0.1.7 安装包重新安装；诊断和新段落命名空间会被旧版本忽略。需要精确回到升级前状态时恢复此前的数据目录备份。

本项目没有 Git 元数据。修改前源码保存在 `output/cache-optimization-backup-20261017`；模块边界分别对应诊断、前缀、实验调度、段落缓存及版本拆分，便于独立检查和撤销。实验调度可直接取消环境变量恢复默认发送方式。
